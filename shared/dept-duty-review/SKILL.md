# 总行部门职能职责梳理

## 用途

以各部门自己反馈的职责原文为「具体职责」列内容源（逐字保留，仅校准用词），综合三份文件形成「调整后职责」列（增删改留痕）。每个部门一个 Sheet。

## 三份参考文件（优先级从高到低）

1. **机构设置请示（如 0910 请示）**——最高优先级，必须完全遵守。部门新设／撤销／合并／更名／职能划转／剥离，一律以此为准。
2. **各部门反馈表的「调整建议」列**（调整类型、调整原因、其它调整建议、备注）——各部门自提的调整意愿，作为调整依据，不擅自采纳。
3. **国有大行总行部门职责与二级机构设置信息**——优先级靠后。用于**颗粒度与写法**参照：不知道怎么写、或有空缺时，找其对应职责来学写；**颗粒度必须按这个文件**。

## 触发词

- 梳理 / 过一遍 / 修订 + 部门名（如「梳理党办」「把审计部过一遍」）
- 按【基准文件】梳理 XX 部门
- 生成总行部门职能职责梳理表
- 回检 / 反向核对 + 部门名（如「回检运营管理部」「把审计部反向核对一遍」）
- 抽象职能 / 填主要职能 + 部门名（如「把 XX 部门的职责抽象成职能」「填 XX 部门的主要职能列」）

## 开工前必须确认（硬闸口，缺一不启动）

1. **harness（输入材料）**：①机构设置请示（基准文件）；②各部门反馈职责材料（0526 汇总表，其「具体职责」列是内容源，其「调整建议」列是调整依据）；③本次要梳理哪些部门（部门清单）。
2. **动态规则**：本次生效的归口规则（员工行为管理怎么三分、文优归谁、大福利归谁等），不写死，每次由用户现给。
3. **输出参数**：版本号、输出路径（默认 `总行一级部门调整/` 下）。

## 工作流：单部门 → 逐条确认 → 定稿 → 下一部门

对一个部门：

1. **具体职责列**＝反馈材料中该部门自己写的职责原文，逐字保留，**只校准用词／错别字／明显笔误**，不改实质内容、不做增删改。
2. **调整后职责列**＝综合三份文件形成的结论稿：
   - 先按请示做部门调整（新设／撤销／合并／更名／划转／剥离），确定哪些职责删、哪些划入、哪些补入；
   - 再看反馈表「调整建议」列（部门自提），作为调整依据；
   - 颗粒度与写法参照国有大行文件；
   - 对反馈原文**过于啰嗦的，精拣合并**（精炼冗词、合并同类项、统一动词），在调整后职责中体现。
3. **留痕**（在「调整后职责」列体现，相对「具体职责」原文，形式参照 10.09 修稿，词级标注）：
   - 〔不变〕黑——调整后仍保留的原文；
   - 〔删〕删除线——删除的字眼／条目，原文保留原位加删除线；
   - 〔改〕〔增〕红色——改写、精拣合并、新增的字眼／条目；
   - 〔冲突〕品红——请示未表述、归属有争议、或仅部门自提的，标【待明确】，不替用户拍板。
4. **用户逐条确认**，有异议当轮改；用户明确说「定稿」后，才写入输出 xlsx。未定稿不写入。
5. 进入下一个部门。

## 工作流二：反向核对 → 抽象职能填列 → 回检（可单独触发，也可跟在「梳理」后）

对已定稿的「调整后职责」，反向核对其是否贴合权威口径，再把职责抽象为「主要职能」填列。

### 核对基准（写死默认，每部门问询选取）

1. **机构设置请示**（如 0910 请示）——最高权威，未表述的一律标【待明确】；
2. **现行发文·主要职能**（如 川银发〔2020〕4号）——部门源头职能；
3. **现行发文·二级部门职责**（如 川银发〔2021〕76号）——颗粒度细节，挖遗漏与移交；
4. **国有大行部门职责表**——颗粒度写法参照。

> 每个部门开工前，先问询本次核对采用哪几份基准（默认以上全部）；主人指定后按其执行。

### 步骤（逐部门闭环）

1. **反向核对**：拿「调整后职责」列逐条对照基准，判【遗漏／冗余／一致】三类，出核对清单给主人确认；只出清单，不动文件。
2. **落笔**：主人确认后——先在「调整后职责」列补遗漏（红新增）、标移交（灰删除线）；再把职责抽象为「主要职能」，以 0703 比对表 **M 列（部门职责·调整后）** 为基础整段搬入再改（红/灰/黑留痕）。
3. **回检**：一个部门走完「核对→确认→落笔」再进下一个。

### 本阶段颜色约定（三色，区别于正向六色）

| 标记 | 字色 | 删除线 |
|---|---|---|
| 保留 | 黑 FF000000 | 无 |
| 新增／改写 | 红 FFFF0000 | 无 |
| 删除／移交 | 灰 FF7F7F7F | **有** |

删除／移交项在留痕段集中标注去向（括注依据，如「移交内控合规部·0910三(二)12」）。

### 技术铁律

- 「具体职责」列原文始终不动；补遗漏与标移交做在「调整后职责」列（新增红、移交灰删线），抽象职能做在「主要职能」列（红/灰/黑三色）。
- **禁用 openpyxl 的插入行**（本文件 inline-string 单元格会静默丢失）；改行结构一律整表重建，见 trace-tech.md。
- 读分段着色必须 `rich_text=True`；颜色给 8 位 ARGB、显式给色。

## 输出契约

- 一个 xlsx：`总行部门职能职责梳理-<版本号>.xlsx`，放 `总行一级部门调整/`
- 结构：总览 Sheet + 每部门一个 Sheet，列＝`部门名称｜主要职能｜具体职责｜备注｜调整后职责`
- 具体职责＝反馈原文（仅校准用词）；调整后职责＝综合结论（增删改留痕）
- 主要职能＝定位句＋抽象后的职能清单，工作流二以 0703 M 列为骨架填列（三色留痕）
- 格式参照：`总行部门职能职责梳理-10.09修稿.xlsx`

## 数据获取通道（ima 优先，本地兜底）

- **优先走 ima 知识库**：材料在 ima「日常工作文件库」等知识库时，通过 ima-mcp 连接器检索获取（未连接时提示用户开启）。
- **找不到才本地**：ima 检索不到该材料时，再读本地工作区文件。

## 固定规则（写死，每次生效）

审核原则、颗粒度规范、颜色约定、效力顺序与底线，见 `references/rules.md`；输出格式与列语义见 `references/output-format.md`；留痕技术见 `references/trace-tech.md`。

## 绝不做什么

- 请示为唯一权威底线：请示明确写到的调整必须执行；请示**未表述**的标【待明确】，不擅自按反馈表或比对表落位，不引用不存在的条文
- 「具体职责」列只校准用词，不做增删改；增删改只体现在「调整后职责」列
- 反馈表的「调整建议」「移交意愿」只如实带入备注，不替用户采纳
- 归属有争议的不替用户拍板，标冲突交用户定
- 不改反馈材料与请示原文，只在产出副本上做留痕
- 用户未说「定稿」的部门，不写入输出文件
- 反向核对只出清单不动文件，主人确认后才落笔
- 「具体职责」列原文始终不动；改动只落在「调整后职责」列（补遗漏／标移交）与「主要职能」列（抽象职能）
