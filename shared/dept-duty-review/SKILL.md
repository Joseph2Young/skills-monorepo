# 总行部门职能职责梳理

## 用途

以各部门自己反馈的职责原文为「具体职责」列内容源（逐字保留，仅校准用词），综合三份文件形成「调整后职责」列（增删改留痕）。每个部门一个 Sheet。

「调整后职责」列一律按**四类条款骨架**成稿：第一类规划统领 → 第二类业务功能 → 第三类队伍建设与客户关系（仅四家）→ 第四类公共类三条 → 末条完成交办。结构、句式、编号与自检清单见 `references/duty-format.md`。

## 三份参考文件（优先级从高到低）

1. **机构设置请示（如 0910 请示）**——最高优先级，必须完全遵守。部门新设／撤销／合并／更名／职能划转／剥离，一律以此为准。
2. **各部门反馈表的「调整建议」列**（调整类型、调整原因、其它调整建议、备注）——各部门自提的调整意愿，作为调整依据，不擅自采纳。
3. **国有大行总行部门职责与二级机构设置信息**——优先级靠后。用于**颗粒度与写法**参照：不知道怎么写、或有空缺时，找其对应职责来学写；**颗粒度必须按这个文件**。

## 触发词

- 梳理 / 过一遍 / 修订 + 部门名（如「梳理党办」「把审计部过一遍」）
- 按【基准文件】梳理 XX 部门
- 生成总行部门职能职责梳理表
- 回检 / 反向核对 + 部门名（如「回检运营管理部」「把审计部反向核对一遍」）
- 抽象职能 / 填主要职能 + 部门名（如「把 XX 部门的职责抽象成职能」「填 XX 部门的主要职能列」）
- 按四类格式编写 / 套模板 / 统一格式重排 + 部门名（如「按四类格式重写公司金融部」「把计财部职责按模板套一遍」「条款结构统一一下」）
- 全自动模式 / 自动梳理 / 主agent+subagent（批量逐部门核查，主 Agent 逐条拍板并留决策台账，见工作流三）

## 开工前必须确认（硬闸口，缺一不启动）

1. **harness（输入材料）**：①机构设置请示（基准文件）；②各部门反馈职责材料（0526 汇总表，其「具体职责」列是内容源，其「调整建议」列是调整依据）；③本次要梳理哪些部门（部门清单）。
2. **动态规则**：本次生效的归口规则（员工行为管理怎么三分、文优归谁、大福利归谁等），不写死，每次由用户现给。
3. **部门类型四要素**（每部门一次性确认，缺省按 `references/duty-format.md` 默认归类表执行并在交付时说明）：业务部门／中后台部门；有无主管条线；是否第三类部门（仅公司金融、零售金融、同业业务、运营管理）；科技圈层（一圈层／二圈层及以上／三圈层）。另确认是否含总行本级经办职能。
4. **输出参数**：版本号、输出路径（默认 `总行一级部门调整/` 下）。

## 工作流：单部门 → 逐条确认 → 定稿 → 下一部门

对一个部门：

1. **具体职责列**＝反馈材料中该部门自己写的职责原文，逐字保留，**只校准用词／错别字／明显笔误**，不改实质内容、不做增删改。
2. **调整后职责列**＝综合三份文件形成的结论稿：
   - 先按请示做部门调整（新设／撤销／合并／更名／划转／剥离），确定哪些职责删、哪些划入、哪些补入；
   - 再看反馈表「调整建议」列（部门自提），作为调整依据；
   - 颗粒度与写法参照国有大行文件；
   - 对反馈原文**过于啰嗦的，精拣合并**（精炼冗词、合并同类项、统一动词），在调整后职责中体现；
   - **最后按四类条款骨架成稿并排序**：第一类规划统领 → 第二类业务功能 → 第三类队伍建设与客户关系（仅四家）→ 第四类公共类三条 → 末条完成交办；结构、句式与编号见 `references/duty-format.md`，出稿前过一遍该文件的成稿自检清单。
3. **留痕**（在「调整后职责」列体现，相对「具体职责」原文，形式参照 10.09 修稿，词级标注）：
   - 〔不变〕黑——调整后仍保留的原文；
   - 〔删〕删除线——删除的字眼／条目，原文保留原位加删除线；
   - 〔改〕〔增〕红色——改写、精拣合并、新增的字眼／条目；
   - 〔冲突〕品红——请示未表述、归属有争议、或仅部门自提的，标【待明确】，不替用户拍板。
4. **用户逐条确认**，有异议当轮改；用户明确说「定稿」后，才写入输出 xlsx。未定稿不写入。
5. 进入下一个部门。

## 工作流二：反向核对 → 抽象职能填列 → 回检（可单独触发，也可跟在「梳理」后）

对已定稿的「调整后职责」，反向核对其是否贴合权威口径，再把职责抽象为「主要职能」填列。

### 核对基准（写死默认，每部门问询选取）

1. **机构设置请示**（如 0910 请示）——最高权威，未表述的一律标【待明确】；
2. **现行发文·主要职能**（如 川银发〔2020〕4号）——部门源头职能；
3. **现行发文·二级部门职责**（如 川银发〔2021〕76号）——颗粒度细节，挖遗漏与移交；
4. **国有大行部门职责表**——颗粒度写法参照。

> 每个部门开工前，先问询本次核对采用哪几份基准（默认以上全部）；主人指定后按其执行。

### 步骤（逐部门闭环）

1. **反向核对**：拿「调整后职责」列逐条对照基准，判【遗漏／冗余／一致】三类，出核对清单给主人确认；只出清单，不动文件。
2. **落笔**：主人确认后——先在「调整后职责」列补遗漏（红新增）、标移交（灰删除线）；再把职责抽象为「主要职能」，以 0703 比对表 **M 列（部门职责·调整后）** 为基础整段搬入再改（红/灰/黑留痕）。
3. **回检**：一个部门走完「核对→确认→落笔」再进下一个。

### 本阶段颜色约定（三色，区别于正向六色）

| 标记 | 字色 | 删除线 |
|---|---|---|
| 保留 | 黑 FF000000 | 无 |
| 新增／改写 | 红 FFFF0000 | 无 |
| 删除／移交 | 灰 FF7F7F7F | **有** |

删除／移交项在留痕段集中标注去向（括注依据，如「移交内控合规部·0910三(二)12」）。

### 技术铁律

- 「具体职责」列原文始终不动；补遗漏与标移交做在「调整后职责」列（新增红、移交灰删线），抽象职能做在「主要职能」列（红/灰/黑三色）。
- **禁用 openpyxl 的插入行**（本文件 inline-string 单元格会静默丢失）；改行结构一律整表重建，见 trace-tech.md。
- 读分段着色必须 `rich_text=True`；颜色给 8 位 ARGB、显式给色。

## 工作流三：全自动模式（主 Agent + 逐部门 Subagent）

触发词：**全自动模式 / 自动梳理 / 主agent+subagent**。用于批量、无人值守地把一批部门按「自上而下」跑完，主 Agent 逐条拍板并留可追溯的决策台账，供主人次日复核。

### 角色分工

| 角色 | 职责 |
|---|---|
| 主 Agent（拍板者·编排者） | 逐部门派发核查；对 Subagent 交回的核对结论逐条拍板；逐条写入决策台账；拍板后关闭该 Subagent |
| Subagent（核查者·一次一部门） | 只核查不拍板、不写文件；产出「职能基线→核对结论→细化职责」+ 待明确清单，交回主 Agent |

### 流程（逐部门闭环）

1. 主 Agent 取下一部门 → **新开一个 Subagent**，注入该部门材料（P 基线、C 列反馈、0910 约束、颗粒度参照）与任务卡。
2. Subagent 核查：填 B 列（逐条 + diff）→ 逐条对照 C 列出核对结论 → 生成 E 列细化拟稿 → 单列待明确清单。
3. 主 Agent 逐条拍板（保留/修改/删除/新增/归口），逐条写入决策台账（append-only）。
4. 拍板通过 → **关闭该 Subagent** → 下一部门。
5. 部门清空 → 主 Agent 汇总台账，交主人次日复核。

### 主 Agent 必拍板的决策点（每部门 5 类）

1. 每条职能结论：保留 / 修改 / 删除（划转去向）/ 新增（是否纳入）。
2. 待明确／冲突项归口：如退休人员服务、个人信息保护、股本管理、宏观政策分工。
3. 新增候选（C 有 P 无）：纳入 or 不纳入。
4. 定位句：用 P 的 or 上一轮的。
5. 措辞统一：如「运营管理」vs「建设及管理」、「牵头」vs「操作性职责」。

### 硬约束

- Subagent 只核查不拍板；拍板权在主 Agent。
- 每部门一个新 Subagent，不跨部门复用上下文。
- 冲突/待明确不得臆测，交主 Agent 拍板并记录。
- 决策台账 append-only，历史不可改，供主人次日复核。

> 完整规范（角色卡片、Subagent 任务卡模板、台账字段与枚举、异常处理）见 `references/auto-mode.md`。

## 工作流四：按四类格式成稿（可单独触发，也是工作流一的收尾步骤）

触发词：**按四类格式编写 / 套模板 / 统一格式重排**。把「调整后职责」列从随手排的条目，重排为统一条款骨架；也可对一个已定稿部门单独套一遍。

### 条款骨架（顺序固定，编号连续、不留空号）

| 条序 | 条款 | 适用范围 |
|---|---|---|
| 第 1 条 | **第一类 规划统领**：条线长期规划 → 中长期计划 → 年度（短期）目标 → 制度研究管理；无主管条线的改「协助制订…按计划执行」 | 全部 |
| 第 2—X 条 | **第二类 业务功能**：业务部门写分管什么业务、负责哪些业务、与相邻部门的切口；中后台按职能模块，每条先定集团／全行／总行本级，本级单列起条 | 全部 |
| 第 X+1 条 | **第三类 队伍建设与客户关系管理** | 仅公司金融（普惠配合）、零售金融、同业业务、运营管理四家 |
| 第 X+2 条 | **第四类① 数智化转型**（单独成条） | 全部 |
| 第 X+3 条 | **第四类② 条线及本部门内控合规与风险管理**（标准句逐字沿用，单独成条） | 全部 |
| 第 X+4 条 | **第四类③ 人员管理·队伍建设·党建·日常综合事务** | 全部 |
| 末条 | **完成上级交办的其他工作** | 全部 |

### 落笔规则

1. **条号不落表**：E 列一事一行，行序即条序；条号只出现在 D 列备注与留痕括注（如「并入第 5 条」）。
2. **四类顺序不可打乱**；某类不适用则整段前移，不占空号（无第三类的部门，第四类从第 X+1 条起）。
3. 单条 30～80 字、动词起首；不写系统、平台、模型、数据表名称；不写「加强」「推进」「提升」这类无对象空动作。
4. **科技二圈层及以上**部门，第二类须含「牵头本条线系统建设需求管理」类条款；三圈层不写。圈层结论默认记 D 列备注。
5. 一部门 8～20 条；超上限先看第二类模块能否合并，不为压条数牺牲已定稿内容。条数与类别分布见 `references/duty-format.md`。
6. 出稿前逐项过 `references/duty-format.md` 第九节成稿自检清单，10 项全过才算完成。

### 留痕

C 列原文不动；E 列按四类重排后，骨架新增要素与无原文对应的新条款标新增色、被合并或替换的原条目整条标删除色并括注去向。本轮用三色还是六色由开工时确认，一轮只用一套（见 `references/duty-format.md` 第八节），不因结构重排改变颜色语义。

## 工作流五：6 列版式逐部门出稿（1019 新模板）

主人给 6 列模板（部门职能｜职能模块｜具体职责｜调整需求｜调整后建议职能模块｜调整后建议职责）、逐部门提供 0526 原表 sheet、逐个确认时走这条。

1. **B/C 列从 0526 对应部门原行程序读取整行照抄**，不手抄；D 列按实际处置逐行写，保留不动的行留空（不写「不变／新增／移交」四字类型）。
2. **E/F 按四类骨架重排，同类项必须合并成主条**：办文办会一条（股东会＋董事会及专委会＋党委会及议事协调机构＋行长办公会及高管层专委会＋文稿），决议与督查督办一条；被并条整条灰删＋红括注「（并入第 X 条）」，集中置于主条之后。**禁止「删掉重复的字、两条各自还在」这种破而未立的做法**。
3. **层级词：只有战略规划写「集团」，其余业务管理一律「全行」**；本条无战略规划内容时不硬加集团。
4. **删改项集中到句末灰色括注**，正文只留保留项与新增项——WPS 会把相邻 run 的删除线画过界，紧邻的红字会看起来带删除线。
5. 出稿后跑校验：B/C 与 0526 逐字一致、三色计数、保留段关键词去重（决议督办／请示报告／综合性文稿／公司治理制度／档案管理等各只命中一处）。
6. 每部门确认后追加 sheet；改前备份 xlsx 与数据脚本，交付时给出回退命令。

细节、版式参数、三办先例台账见 `references/6col-merge-rules.md`。

## 输出契约

- 一个 xlsx：`总行部门职能职责梳理-<版本号>.xlsx`，放 `总行一级部门调整/`
- 结构：总览 Sheet + 每部门一个 Sheet，列＝`部门名称｜主要职能｜具体职责｜备注｜调整后职责`
- **6 列版式（1019 新模板）例外**：列＝`部门职能｜职能模块｜具体职责｜调整需求｜调整后建议职能模块｜调整后建议职责`，B/C 照抄 0526，D 列写实际处置，见 `references/6col-merge-rules.md`
- 具体职责＝反馈原文（仅校准用词）；调整后职责＝综合结论（增删改留痕）
- 主要职能＝定位句＋抽象后的职能清单，工作流二以 0703 M 列为骨架填列（三色留痕）
- **条款结构以 `references/duty-format.md` 为准**；`总行部门职能职责梳理-10.09修稿.xlsx` 只作版式参照

## 固定规则（写死，每次生效）

审核原则、颗粒度规范、颜色约定、效力顺序与底线，见 `references/rules.md`；输出格式与列语义见 `references/output-format.md`；留痕技术见 `references/trace-tech.md`。

## 绝不做什么

- 请示为唯一权威底线：请示明确写到的调整必须执行；请示**未表述**的标【待明确】，不擅自按反馈表或比对表落位，不引用不存在的条文
- 「具体职责」列只校准用词，不做增删改；增删改只体现在「调整后职责」列
- 反馈表的「调整建议」「移交意愿」只如实带入备注，不替用户采纳
- 归属有争议的不替用户拍板，标冲突交用户定
- 不改反馈材料与请示原文，只在产出副本上做留痕
- 用户未说「定稿」的部门，不写入输出文件
- 反向核对只出清单不动文件，主人确认后才落笔
- 「具体职责」列原文始终不动；改动只落在「调整后职责」列（补遗漏／标移交）与「主要职能」列（抽象职能）
- 不按四类骨架排序的稿子不出：第三类只在四家出现、「完成…交办」全表只一条、条号不写进单元格
- 无主管条线的部门不写成「制订全行××规划」，一律「协助制订…按计划执行」
- 普惠、消金是产品管理部门，不设客户队伍，不写「负责客户关系管理」
- 第四类合规条逐字沿用标准句，不各写各的；末条统一为「完成上级交办的其他工作」，不按部门分交办主体
