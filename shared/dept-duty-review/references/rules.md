# 固定规则（写死，每次生效，不每次确认）

## 一、审核原则（三条，沿用）

1. **消失部门**：职能必须有人接盘（由新设部门或原有部门承接）。旧职能以比对表的「调整前职责」列为准。
2. **新设部门**：职能必须从老部门剥离，严禁凭空新增。基准文件里有表述的按基准文件为准。
3. **扯皮事项**：一项职能由业务部门与科技/中后台共同承担时，业务部门考核权超过 60% 的归业务部门；科技部门只评价技术建设，业务部门评价需求满足度。

## 二、颗粒度规范

1. **主要职能**写「管什么」——定位、归口（牵头）范围、覆盖边界、主要管理对象。一段话，不罗列具体工作事项。
2. **具体职责**写「做什么」——一事一条，每条以「负责／牵头／组织／拟定／审核／督导／承办／完成」等动词起首，单条 30～80 字。
3. **颗粒度对齐**：同一部门内各条职责颗粒度相当，同类事项合并，避免「一条只写一句话」或「一条涵盖多个不相关事项」。
4. **不写工具与手段**：系统、平台、模型、数据集市、系统群等实现手段不作为职责；职责只表述管理事项、管理动作、管理结果。
5. 职责条数一般 6～15 条。
6. **精拣合并**：反馈原文过于啰嗦的，在「调整后职责」中精炼冗词、合并同类项、统一动词（牵头／统筹／负责／推动），删括号内技术细目与自我评价尾缀，口径向上归并。精拣后的文字用红字标改写、被删的字眼加删除线。
7. **末尾固定两条**（每个部门「调整后职责」列末尾，固定格式）：
   - 倒数第二：负责落实条线及本部门合规管理，负责条线合规检查与问题整改的组织实施，落实条线消保、反洗钱、案防等工作，指导与监督条线从业人员履职尽责。
   - 倒数第一：完成上级交办的其他工作。
   - 部门反馈原文里已有的「完成……交办的其他工作」统一改为「完成上级交办的其他工作」；合规条为固定新增。

## 三、颜色约定（词级 diff 六色）

「调整后职责」列用词级标注——一条职责内部，对比原文标出每个字词的改动：

| 标记 | 字色 | 删除线 | 说明 |
|---|---|---|---|
| 保留 | 黑 `FF000000` | 无 | 原文照录、未改的字词 |
| 改写 | 蓝 `FF0000FF` | 无 | 精拣合并、改表述的字词 |
| 新增 | 深绿 `FF006400` | 无 | 原文没有、请示补入/接收/末尾固定的字词 |
| 删除 | 红 `FFFF0000` | **有** | 原文有、删掉的字词（留痕段附去向） |
| 待明确 | 品红 `FFFF00FF` | 无 | 去向未定，【待明确】 |
| 交叉 | 橙 `FFFF6600` | 无 | 【重】【交】 |

**留痕口径**：被删除的整条原条目在「调整后职责」列末段集中留痕，格式＝职能模块名加删除线＋括注去向，前加「【留痕】」标记行；整条原文已在「具体职责」列，留痕段不重复放原文。

**备注列语义**：D 列写人能读懂的调整说明，不用内部编号——
- 保留：`不变`（可空）
- 新增/接收：`接收XX`、`0910三15补入`、`末尾固定`
- 待明确：`待明确`（附冲突双方）
- 删除/移交：在留痕段标注去向，不占备注列

## 三′、颗粒度调整的落点（硬规则）

**颗粒度调整只在「调整后职责」列完成**：「具体职责」列照录反馈原文（仅校准用词，不精拣）；「调整后职责」列按国有大行颗粒度精拣合并——中文序号「一、二、三」、一事一条、每条一个管理动作、30～80 字、动作链完整。

## 四、效力顺序与底线（硬要求）

1. 效力顺序：基准文件（请示）＞ 部门比对表 ＞ 过程材料。三者冲突，一律以请示为准。
2. **请示为唯一权威基准**：
   - 请示**明确写到的**调整（划转／剥离／新设／合署／更名／下沉）→ 必须执行，逐条落实；
   - 请示**未表述**的事项 → 一律标【待明确】，**不擅自按比对表或部门反馈落位**，不引用不存在的条文；
   - 部门反馈的「其它调整建议」「部门移交意愿」→ 只如实带入备注，不替用户采纳。
3. 判定每条调整时，先回到请示原文核对是否有明文依据，没有明文的不得标为「新增／删除」，只能标【待明确】。

## 五、反向核对与抽象职能（工作流二专用）

### 核对口径

1. 拿「调整后职责」逐条对照基准，判三类：
   - **遗漏**：基准有、调整后职责无 → 补；
   - **冗余**：调整后职责有、基准无 → 删或移交；
   - **一致**：两边都有 → 保留。
2. 判定「移交」前回请示原文核对明文依据；请示**未表述**的一律【待明确】，不擅自判定移交。
3. 请示明文已定归口（如「反洗钱管理归内控合规部」）而调整后职责相冲突时，以请示为准，原条目标删除线＋去向括注。

### 抽象职能的颗粒度

- 以 0703 比对表 **M 列（部门职责·调整后）** 为骨架整段搬入「主要职能」列，再按核对结论增删改。
- 职能写「管什么」的归口短语，比「调整后职责」高一档、更凝练，不逐条罗列操作细节。
- 保留 M 列既有措辞（如「牵头」「统筹」），除非主人另行裁决（如「牵头」改「承担…操作性职责」）。

### 三色约定（本阶段专用，区别于正向六色）

| 标记 | 字色 | 删除线 |
|---|---|---|
| 保留 | 黑 `FF000000` | 无 |
| 新增／改写 | 红 `FFFF0000` | 无 |
| 删除／移交 | 灰 `FF7F7F7F` | **有** |

删除／移交项在留痕段集中标注去向，括注依据（如「移交内控合规部·0910三(二)12」）。

### 整表重建铁律

- **禁用 openpyxl 的 `insert_rows`／`delete_rows`**：本文件单元格为 inline-string，openpyxl 插行后保存会随机丢失被移动的单元格。
- 改行结构（增行／删行／重排）一律整表重建：快照 tabColor、列宽、表头样式 → 删除旧 sheet、新建同名 sheet → 恢复 tabColor、列宽、表头 → 逐行写 value＋样式＋富文本 runs。
- 重建后核验：sheet 总数不变、tab 颜色保留、其余 sheet 未受影响、富文本颜色正确。
