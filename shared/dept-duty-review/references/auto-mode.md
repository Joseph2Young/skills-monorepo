# 全自动模式规范（主 Agent + 逐部门 Subagent）

> 本文件是「工作流三：全自动模式」的详细规范。触发词：全自动模式 / 自动梳理 / 主agent+subagent。

## 一、什么时候用

- 一批部门（多个）需要按「自上而下」批量跑完职能梳理（P 基线 → B 列 → 核对 C 列 → 细化 E 列）。
- 主人明确说「全自动模式」或「主 agent + subagent」。
- 主人要求决策可追溯、次日可复核。

不适用：只梳理单个部门、需要主人逐条人机确认的精细场景（此时走工作流一/二）。

## 二、角色卡片

### 主 Agent（拍板者·编排者）

- 持有权威约束：0910 请示、0703 比对表 P 基线、颜色口径（黑 FF000000／红 FFFF0000／灰删线 FF7F7F7F）、颗粒度规则、四类条款骨架（第一类规划统领／第二类业务功能／第三类队伍建设与客户关系／第四类公共条三条／末条完成高级管理层交办的其他工作，见 duty-format.md）。
- 编排：维护「部门清单 + 决策台账」，逐部门派发 → 确认 → 关闭。
- 拍板：对 Subagent 交回的每条核对结论做最终裁决，逐条记录依据。
- 兜底：Subagent 卡住、数据读不到、冲突无法解决时，由主 Agent 直接处理或标【待补充】交主人。

### Subagent（核查者·一次一部门）

- 只核查、不拍板、不写文件。
- 输入：部门名 + P 基线 + C 列反馈 + 0910 约束 + 颗粒度参照 + 任务卡。
- 产出：职能基线（B 列）+ 核对结论（逐条）+ 细化职责（E 列拟稿）+ 待明确清单。

## 三、Subagent 任务卡模板（主 Agent 派发时套用）

```
你是部门职能职责核查 Subagent，只核查、不拍板。本次核查「{部门名}」。

【输入材料】
- P 基线（0703 表「0910调整后」部门职责，含黑/红/绿删线 diff 痕迹）：
  {P 文本}
- C 列反馈（部门自提职责原文）：
  {C 文本}
- 权威约束：0910 请示（该部门相关划转/新设/合并条款）
- 颗粒度参照：国有大行总行部门职责表
- 条款结构：四类骨架（第一类规划统领 → 第二类业务功能 → 第三类队伍建设与客户关系（仅四家）→ 第四类公共条三条 → 末条完成高级管理层交办的其他工作）

【任务】
1. 把 P 基线按「；」逐条拆成职能，填 B 列（定位句 + 逐条职能；绿删线→灰删线 FF7F7F7F）。
2. 逐条对照 C 列，判「保留/修改/删除/新增」，说明核对结论与依据。
3. 对核对通过的职能，生成颗粒度更细化的 E 列职责（黑=保留、红=细化/新增、灰删线=删除）。
4. 按四类骨架重排 E 列条款顺序，条号不落表，逐项过 duty-format.md 第九节自检清单。
5. 把「待明确/冲突」项单列清单，交主 Agent 拍板。

【产出格式】
一、职能基线（逐条）
二、核对结论（逐条：保留/修改/删除/新增 + 说明）
三、细化职责（E 列拟稿，带 diff 痕迹）
四、待明确清单（逐条：冲突双方 + 建议依据）

【硬约束】
- 只核查不拍板；不臆测，缺失标【待补充：缺什么/向谁要】。
- 不写文件，只产出文本交主 Agent。
```

## 四、主 Agent 拍板决策点（每部门 5 类）

1. **每条职能结论**：保留 / 修改 / 删除（划转去向）/ 新增（是否纳入）。
2. **待明确/冲突归口**：如退休人员服务（党办 or 行政服务部）、个人信息保护（内控合规部 or 法规部）、股本管理（战略部）、宏观政策分工（研究规划部）。
3. **新增候选**（C 有 P 无）：纳入 or 不纳入。
4. **定位句**：用 P 的 or 上一轮的。
5. **措辞统一**：「运营管理」vs「建设及管理」、「牵头」vs「操作性职责」等。

## 五、决策台账（可追溯，append-only）

- 位置：项目目录 `总行一级部门调整/主Agent决策台账.md`。
- 规则：只追加、不改历史；每条含依据；供主人次日复核。

| # | 时间 | 部门 | 条目 | 决策类型 | 结论 | 依据 | 状态 |
|---|---|---|---|---|---|---|---|
| 1 | 2026-10-15 | 全局 | 推进节奏 | 口径 | 先样板后批量 | 主人拍板 | 已拍板 |

- **决策类型枚举**：保留 / 修改 / 删除 / 新增 / 归口 / 待明确 / 口径。
- **状态枚举**：已拍板 / 待复核 / 已复核（主人次日复核后改「已复核」）。

## 六、异常处理

| 异常 | 处理 |
|---|---|
| Subagent 数据读不到 | 交主 Agent 重读或走 ima 兜底；仍缺则标【待补充】 |
| C 与 P 数据打架 | 不择一，交主 Agent 按 0910 权威裁决并记录 |
| 冲突无法解决 | 标【待明确】+ 冲突双方，交主人拍板，不臆测 |
| Subagent 产出不符格式 | 主 Agent 退回重核一次；再不行主 Agent 自己补 |

## 七、与工作流一/二的关系

- 工作流一（自下而上，C→E）与工作流二（反向核对）是「单部门、人机逐条确认」的精细模式。
- 工作流三（全自动）是「批量、主 Agent 代拍板」的无人值守模式，适用于已定口径、主人次日复核的场景。
- 三套工作流共享同一套颜色约定、颗粒度规则、技术铁律（见 rules.md / trace-tech.md）。
