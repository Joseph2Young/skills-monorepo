# 输出格式与颗粒度

## 一、工作簿结构

`总行部门职能职责梳理-<版本号>.xlsx`，两个部分：

1. **总览 Sheet**：调整前后部门对照，列＝序号｜部门名称（调整前）｜部门是否发生调整｜已有职能是否需要调整｜后续职能是否发生变化｜后续变动情况。
2. **每部门一个 Sheet**：Sheet 名＝部门规范名称，列＝`部门名称｜主要职能｜具体职责｜备注｜调整后职责`（5 列）。

## 二、单部门 Sheet 布局

| 列 | 内容 |
|---|---|
| A 部门名称 | 部门规范名称（合署办公并列填写，标注「（合署办公）」） |
| B 主要职能 | 一段话定位，见 rules.md 颗粒度规范 |
| C 具体职责 | **反馈表原文**，逐字保留，只校准用词／错别字／明显笔误，不做增删改 |
| D 备注 | 调整类型（不变/新增/接收/移交/更名/合署）、依据文件、移交去向、待明确事项 |
| E 调整后职责 | **综合三份文件的结论稿**，增删改留痕在此列体现（删=删除线、增=绿、改=蓝、冲突=品红） |

**关键区分**：
- C 列「具体职责」＝各部门在 0526 反馈表里**自己写的原文**，是输入，只校准用词；
- E 列「调整后职责」＝综合请示（最高优先级）＋反馈表「调整建议」＋国有大行颗粒度 形成的**结论稿**，是输出，增删改留痕只做在这里。

**备注列语义**：D 列是逐条处置指令——「合并为第 X 条」「合并至第 X 条」「重复，建议删除」「移交给 XX 部」「部门移交意愿（XX）」「接收 XX 部移交」等。

## 三、颗粒度参照（国有大行口径）

具体职责用中文序号「一、二、三…」，一事一条，动作链完整。示例（软件中心）：

> 一、按照集团信息科技发展规划及目标，负责全行应用软件开发、应用软件质量控制、应用系统维护工作，制订相关标准、流程和规范并组织实施。
> 二、负责全行应用软件（含自主开发、外购、委托分行开发的应用软件等）开发、功能测试的统一管理。
> 三、负责应用软件开发，包括方案建议书编写和经批准后的方案设计、需求分析、总体设计、详细设计、系统实现和测试。

**要点**：
- 每条以动词起首（负责／按照／根据），一条＝一个管理动作；
- 颗粒度细到「制订制度」「负责管理」「负责监督」「负责检查」这一层；
- 动作链完整：制度 → 管理 → 执行 → 监督 → 后评价，一条职责内可串起来；
- 但**不写工具手段**：系统建设、平台搭建、模型开发等实现手段不列为职责。

## 四、主要职能颗粒度（定位层，区别于具体职责）

主要职能写「管什么」，一段话，不重复罗列具体职责。示例（国有大行总行法律与合规部）：

> 负责制订与维护集团法律合规管理政策制度，确定集团法律合规管理工作规划并组织实施，负责组织集团法律合规管理……

定位、边界、对象说清即可，具体「做什么」放到具体职责列。
