# 输出格式与颗粒度

## 一、工作簿结构

`总行部门职能职责梳理-<版本号>.xlsx`，两个部分：

1. **总览 Sheet**：调整前后部门对照，列＝序号｜部门名称（调整前）｜部门是否发生调整｜已有职能是否需要调整｜后续职能是否发生变化｜后续变动情况。
2. **每部门一个 Sheet**：Sheet 名＝部门规范名称，列＝`部门名称｜主要职能｜具体职责｜备注｜调整后职责`（5 列）。

## 二、单部门 Sheet 布局

| 列 | 内容 |
|---|---|
| A 部门名称 | 部门规范名称（合署办公并列填写，标注「（合署办公）」） |
| B 主要职能 | 一段话定位，见 rules.md 颗粒度规范 |
| C 具体职责 | **反馈表原文**，逐字保留，只校准用词／错别字／明显笔误，不做增删改 |
| D 备注 | 调整类型（不变/新增/接收/移交/更名/合署）、依据文件、移交去向、待明确事项 |
| E 调整后职责 | **综合三份文件的结论稿**，按四类条款骨架成稿并排序（结构见第三节，句式见 duty-format.md），增删改留痕在此列体现 |

**关键区分**：
- C 列「具体职责」＝各部门在 0526 反馈表里**自己写的原文**，是输入，只校准用词；
- E 列「调整后职责」＝综合请示（最高优先级）＋反馈表「调整建议」＋国有大行颗粒度 形成的**结论稿**，是输出，增删改留痕只做在这里。

**备注列语义**：D 列是逐条处置指令——「合并为第 X 条」「合并至第 X 条」「重复，建议删除」「移交给 XX 部」「部门移交意愿（XX）」「接收 XX 部移交」等。

D 列同时记载结构与分类信息（写在部门名称所在行的备注格内）：部门类型（业务部门／中后台部门）、有无主管条线、是否第三类部门、是否含总行本级经办、科技圈层（一圈层／二圈层及以上／三圈层）。这几项是四类骨架的入参，缺了就无法判断条款该用哪版句式。

## 三、E 列条款结构（四类骨架）

一个部门的 E 列从上到下固定为五段，条号不落表（行序即条序），某段不适用则整段前移：

| 条序 | 条款 | 一行写什么 |
|---|---|---|
| 第 1 条 | 第一类 规划统领 | 条线长期规划、中长期计划、年度目标、制度研究管理；无主管条线写「协助…按计划执行」 |
| 第 2—X 条 | 第二类 业务功能 | 业务部门：分管业务＋负责业务＋部门切口；中后台：一个职能模块一行，行首带集团／全行／总行本级限定，本级单列 |
| 第 X+1 条 | 第三类 队伍建设与客户关系 | 仅公司金融（普惠配合）、零售金融、同业业务、运营管理 |
| 第 X+2 条 | 第四类① 数智化转型 | 牵头本部门（本条线）数智化转型 |
| 第 X+3 条 | 第四类② 内控合规与风险管理 | 标准句逐字沿用 |
| 第 X+4 条 | 第四类③ 人员管理·党建·综合事务 | 人员管理与队伍建设、党建、日常综合事务 |
| 末条 | 完成交办 | 完成高级管理层交办的其他工作 |

示例（计划财务部，骨架示意，非定稿）：

> 负责制订全行财务条线发展规划和财务管理制度，组织编制中长期财务计划，制定年度财务目标，负责财税政策研究。
> 负责全行资产负债管理，组织监测和管理资产负债总量和结构，制定月度、季度资产负债计划。
> 负责总行本级财务统一管理，编制总行本级及直属机构财务预算并监控执行。
> 牵头本部门数智化转型，负责业务需求管理与流程线上化，推动本条线系统建设与迭代优化。
> 负责条线及本部门合规管理，组织条线合规检查与问题整改，落实消保、反洗钱、案防等工作。
> 负责本部门人员管理与队伍建设，承担本部门党建、党风廉政建设及日常综合事务。
> 完成高级管理层交办的其他工作。

（第二类只列三条示意，实际按本部门职能模块展开到 4～13 条。）

## 四、颗粒度参照（国有大行口径）

颗粒度照国有大行学，序号不照搬：本表一事一行、单元格内不写「一、二、三」，行序即条序。示例（软件中心，颗粒度参照）：

> 一、按照集团信息科技发展规划及目标，负责全行应用软件开发、应用软件质量控制、应用系统维护工作，制订相关标准、流程和规范并组织实施。
> 二、负责全行应用软件（含自主开发、外购、委托分行开发的应用软件等）开发、功能测试的统一管理。
> 三、负责应用软件开发，包括方案建议书编写和经批准后的方案设计、需求分析、总体设计、详细设计、系统实现和测试。

**要点**：
- 每条以动词起首（负责／按照／根据），一条＝一个管理动作；
- 颗粒度细到「制订制度」「负责管理」「负责监督」「负责检查」这一层；
- 动作链完整：制度 → 管理 → 执行 → 监督 → 后评价，一条职责内可串起来；
- 但**不写工具手段**：系统建设、平台搭建、模型开发等实现手段不列为职责。

## 五、主要职能颗粒度（定位层，区别于具体职责）

主要职能写「管什么」，一段话，不重复罗列具体职责。示例（国有大行总行法律与合规部）：

> 负责制订与维护集团法律合规管理政策制度，确定集团法律合规管理工作规划并组织实施，负责组织集团法律合规管理……

定位、边界、对象说清即可，具体「做什么」放到具体职责列。
